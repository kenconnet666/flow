## 1. 已定的决定

| 项       | 决定                                                                                                                                                           |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 画布     | **SVG 画连线**（连同泳道底色、网关形状、框选框、对齐线、连线预览），**HTML 画节点**（文字换行、焦点、主题照常）；交互全部自研，不引图编辑库                    |
| 范围     | 审批相关的组件全部重新审查、重新做：流程图、设计器、审批按钮、流转记录；缺的能力按 §3 补齐                                                                     |
| 模型     | 仍用 `ProcessDefinition`（泳道 + 节点 + 连线的图，BPMN 子集，纯 JSON）。需求里有带轮次的循环、退回到指定节点、提级、并行汇合，节点树表达不了                   |
| 参考     | 视口、拖动、连线的交互参考 React Flow（`@xyflow/system` 的 XYPanZoom、XYDrag、XYHandle），只借鉴设计，不依赖（它声明不面向其他库，版本还在 0.0.x）             |
| 不用     | AntV X6、LogicFlow：自带渲染与样式体系，和运行时样式引擎、只用 TSX 的约定冲突。Canvas、WebGL、three.js：流程不过百来个节点，用不上，还丢掉 DOM 文字与无障碍    |
| 自动排布 | 保留自己的泳道排布并改进（§2.3）；复杂图要“一键整理”时再评估 ELK 分层布局（按需懒加载，许可证 EPL-2.0，体积先实测）                                            |
| 契约     | 流程定义、运行时类型、校验与问题代号、条件求值、版本差异放 `flow` 仓库的零依赖模型包（TS 与 Java 各一份，共用样例），前后端都按它；本库怎样拿到它见 §6 第 1 条 |
| 管理端   | 定义管理、实例监控、作业、工作日历这些直接对接引擎接口的页面放 `flow` 仓库，用本库搭；本库只放通用的底座与流程组件                                             |
| 顺序     | 底座 → 流程组件 → 运行时组件（§5）                                                                                                                             |
| 做法     | 每个组件开着文档站边做边看：动手前先截图现状、列出问题，做的过程中随时看效果，外观与 API 的实用性一起改；整理与功能分开提交                                    |

## 2. 现状审查（2026-10-24）

### 2.1 FlowDiagram

| 问题                                                                 | 重做时                                                                                               |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 一个渲染函数里画泳道、连线、文字、节点，部件只能经 `propsXxx` 整体改 | 拆成画布与部件（视口、泳道、节点、连线、连线文字、小地图），符合“一个元素一个组件”                   |
| 每次渲染都重新排布；`labelOf` 对每条线在全部节点、连线里线性查找     | 排布结果按定义缓存（computed），查找走 `processGraph` 的索引；拖动时只重算被拖节点和相连的线         |
| 只有横向滚动和“缩小到容器宽”（`fit`），没有平移缩放                  | 接 `usePanZoom`（`wheel: 'pan'`，Ctrl 缩放）、适应视口、缩放档位、小地图                             |
| 连线没有命中区域，不能悬停、选中；读屏只读得到节点，读不到“从哪到哪” | 连线带加粗的透明命中路径，可悬停、选中、聚焦；流程另给一份文字版的“步骤与去向”（`aria-describedby`） |
| 箭头 marker 的 id 用模块计数器                                       | 用 Vue 的 `useId`                                                                                    |

### 2.2 FlowDesigner

| 问题                                                                                   | 重做时                                               |
| -------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| 只能改节点属性：不能增删节点、连线、泳道；处理结果只读；连线的条件、副作用、种类改不了 | 结构编辑全做（§3.2）                                 |
| 会签、表单键、流程级属性（名称、标识、说明、泳道）改不了                               | 属性面板按选中的对象（流程、泳道、节点、连线）切换   |
| 发布时前端自己把版本加一                                                               | 版本号由后端发布时给出：`onPublish` 返回发布后的定义 |
| 每次渲染把整个定义 `JSON.stringify` 一遍来判断有没有改动                               | 由撤销栈的位置判断（保存点）                         |
| 处理人只能从静态的 `groups`、`users` 里选；取流程变量的处理人、时限只显示变量名        | 人员与岗位选择器（远程加载、搜索）；变量引用可以编辑 |
| 没有撤销重做、复制粘贴、键盘操作                                                       | `createHistory` 与画布的键盘操作（§4）               |

### 2.3 layoutProcess（排布）

| 问题                                                                                                | 重做时                                                                                  |
| --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 往回的连线在泳道上沿只错开 3 档，多于三条就重叠；从下层泳道往回的线竖直穿过中间的泳道，可能压住节点 | 通道按需分配，走线避开节点                                                              |
| 同一列空隙里的几条线在同一个横坐标折弯，叠在一起；几条线进同一个节点的同一边挤在一个点              | 端口分配：同一边的线按对端的位置排序、均匀分布；折弯位置错开                            |
| 节点手动定位（`position`）后，连线不避让                                                            | 正交路由避障：自研（可视图加 A\*）为主，libavoid 的 WASM 版作对照（许可证与体积待核实） |
| 每个节点 `lanes.find`、每次出队 `filter` 全部连线，复杂度 O(N·E)                                    | 先建索引                                                                                |

### 2.4 validateProcess（校验）

| 问题                                                                                                                                         | 重做时                                                         |
| -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 问题说明写死中文，不走 `workflowMessages`                                                                                                    | 问题只带 `code` 和参数，文案从语言包取                         |
| 缺结构检查：并行分叉与汇合是否配对（排他分出去的分支进并行汇合会卡住）、退回连线的目标应在上游、提级的目标应进有收件箱的泳道、会签参与人变量 | 补上；规则和后端引擎的发布校验共用一份清单（问题代号两边一致） |

### 2.5 ApprovalActions 与流转记录

- ApprovalActions 只覆盖“处理结果”这一类按钮。认领、退回收件箱、指定、申请改派、转办、委派、加签、抄送、撤回、催办等收件箱动作，
  等后端引擎的契约定了一起做，拆成审批面板（§3.3）。
- `useWorkflowTimeline` 建在 Timeline 上，接口可用；事件种类随契约扩展，重做时复审图标、色调与文案。

### 3.2 流程子路径

- **模型**：`definition`、`validate`（§2.4）、`layout`（改用 `/diagram` 的路由）、`diffProcess(a, b)` 两个版本的差异（节点、连线、属性）。
- **FlowDiagram**：只读视图，建在画布底座上；进度、问题标注、点选节点看那一步的记录、悬停显示处理人与时间。
- **FlowDesigner**：
  - 工具栏：撤销、重做、整理、适应视口、缩放、导入导出 JSON、版本对比、校验状态、发布；
  - 左侧节点面板：拖入或点击添加开始、人工节点、排他与并行网关、结束；
  - 画布：结构编辑（§3.1 的选择、拖动、连线）；泳道的增删、改名、排序、调高度；
  - 右侧属性面板，按选中的对象切换：
    - 流程：名称、标识、说明；
    - 泳道：名称、岗位收件箱；
    - 节点：处理人、时限、超时、处理结果（增删改排序、种类、意见与附件要求、一票否决）、会签、表单键、业务附加信息；
    - 连线：处理结果、条件（条件构造器）、默认、种类（退回、提级）、副作用、文字。
  - 底部问题列表：点一条定位到节点或连线。
- **版本对比**：两版定义并排或叠加，增删改的节点与连线着色。

### 3.3 运行时组件

| 组件             | 内容                                                                                                                |
| ---------------- | ------------------------------------------------------------------------------------------------------------------- |
| 收件箱表格       | QueryTable 的预设：待认领、我的待办、已办、抄送；行内动作（认领、退回收件箱、指定、申请改派）；业务摘要列由使用方给 |
| 审批面板         | 处理结果按钮（ApprovalActions）加意见、附件、业务表单、选择下一处理人；收件箱动作按契约扩展                         |
| 流转记录         | `useWorkflowTimeline` 复审后保留                                                                                    |
| 进度卡           | 给外部参与方看：当前环节、谁在处理、预计何时答复                                                                    |
| 实例详情（组合） | 业务表单、流程图（进度）、流转记录、审批面板的页面组合，放 patterns 或示例                                          |

## 4. 设计器的交互与无障碍

- **键盘**：Tab 在节点、连线之间移动；方向键微调选中的节点（Shift 大步）；Delete 删除；Ctrl+Z / Ctrl+Shift+Z 撤销重做；
  Ctrl+C / Ctrl+V 复制粘贴（连线一起，标识重新生成）；Ctrl+A 全选；Enter 聚焦属性面板；Esc 取消正在拖的连线、清空选择。
- **拖动的替代**：拖动能做的事在属性面板或菜单里都能做（换泳道、连到哪个节点），满足 WCAG 2.5.7。
- **读屏**：节点是按钮，带类型与状态；连线可聚焦，读作“从 A 到 B，处理结果 X”；流程另有文字版的步骤清单。
- **性能**：拖动走响应式的样式绑定，只改被拖的节点与相连的连线；排布与路由的结果按需重算。

## 5. 分步

每步都配文档页、饱满的示例、单元与浏览器测试；开着文档站做，动手前先截图现状、列出要改的外观与 API，做完在文档页上逐项核对。整理与功能分开提交。

1. **画布底座**：`createHistory`；`/diagram` 的视口、选择、拖动、连线、路由与导出。只依赖核心与基础设施，组织架构图、关系图也能用。
2. **通用输入**：条件构造器、人员与组织选择器（核心的 input 目录），FilterBar 的高级筛选接上条件构造器。
3. **模型包**：在 `flow` 仓库建零依赖的模型包（定义、运行时类型、校验与问题代号、条件求值、版本差异，TS 与 Java 各一份），本库的流程组件改按它的类型工作（接法见 §6 第 1 条）。
4. **FlowDiagram 重做**：建在画布底座上，只读视图、进度、问题标注，替换现有实现。
5. **FlowDesigner 重做**：§3.2 的全部内容，接上条件构造器与选择器。
6. **运行时组件与表单**：收件箱表格、审批面板、进度卡、流转记录复审、实例详情的组合；代码表单的运行时（加载、字段权限），之后是表单设计器（[0004](decisions/0004-forms.md)）。
7. **契约扩展**：随后端引擎的表设计一起定，再落到模型包、校验与组件。

旧的 FlowDiagram、FlowDesigner、ApprovalActions 与 `layoutProcess` 在对应的新组件替换后删除，不留兼容层。

## 6. 已定的细节（2026-10-25）

| 项                    | 决定                                                                                                                                                                                   |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 契约放哪              | `flow` 仓库的模型包（见 §1）。待定：本库是公开仓库、CI 要能安装依赖，而 `flow` 是私有仓库、模型包暂不发布，流程组件怎样拿到它在第 3 步之前定（发布模型包，或流程组件挪到 `flow` 仓库） |

| 路由算法              | 先自研正交路由（可视图加 A\*、端口分配、往回连线的通道），纯函数单测；libavoid（WASM）、ELK 只在做“一键整理”时再实测                                                                   |

| 条件构造器、选择器    | 进核心（input）：FilterBar、表单里也用                                                                                                                                                 |

| 示例数据              | 用通用的虚构场景（采购、销售、门店、供应商甲），不用具体项目的业务名词                                                                                                                 |
| 美化                  | 每个组件开工前在文档站截图现状、指出问题；先改流程界面用得最多的表格、表单、卡片、时间线                                                                                               |
| 契约扩展（原第 1 条） | 调用其他流程、自动节点与定时、流转前的守卫、节点级的字段权限、超时提级、收件箱兜底、抄送、转办委派与加签、通知：随 `flow` 的表设计一起定（第 7 步）                                    |
