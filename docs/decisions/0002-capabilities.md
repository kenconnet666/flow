# 0002 能力清单

- 状态：已定（用户 2026-10-26。对照 0004–0007 逐条核对，每节下面注明落在哪份文档；后来新加的能力列在第 13 节）。用户要求"需要的功能第一版都做，尽量完善"
- 来源：warm-flow、FlowLong、Flowable / Camunda 的能力对照，加上真实业务需求里抽出来的通用要求（业务名词不进本仓库）
- 每项注明落在哪里：定义（流程定义 JSON 的字段）、表、接口（引擎的命令或查询）、扩展点

## 1. 定义管理

落实：0005（定义）、0006 的 3.5（命令）、0007 的 3.1（`flow_process`、`flow_definition`、`flow_draft`）。

| 能力 | 说明 | 落在 |
| --- | --- | --- |
| 草稿 | 保存、自动保存、多人编辑时用版本列防覆盖 | 表 `flow_draft`；接口 |
| 校验 | 结构（唯一开始、走得到结束、分叉与汇合配对、退回目标在上游）、引用（处理人解析器、守卫、动作、表单是否已注册） | 接口；校验规则前后端共用一份清单 |
| 发布 | 校验通过才能发布，版本号由后端加一；发布后不可变 | 表 `flow_definition`；接口 |
| 停用、启用 | 停用后不能新发起，进行中的实例照常走完 | 表 `flow_process`；接口 |
| 复制、导入、导出 | JSON；导入时重新校验 | 接口 |
| 版本对比 | 两个版本的节点、连线、属性差异 | 接口（纯函数，两个后端都有） |
| 分类 | 按分类列出、筛选 | 表 `flow_process` |
| 实例迁移到新版本 | 管理员把进行中的实例换到新版本：给出节点的对应关系，校验后迁移，留痕 | 接口；流转记录 |

## 2. 节点与连线

落实：0005 的第 4–6 节。

| 能力 | 说明 | 落在 |
| --- | --- | --- |
| 开始、结束 | 结束带结果（通过、否决、搁置……）；终止结束会取消并行的其他分支 | 定义 |
| 人工节点 | 处理结果（按钮）决定走哪条出边；意见、附件、业务字段的填写要求 | 定义 |
| 排他网关 | 按条件走一条，都不满足走默认 | 定义 |
| 并行网关 | 分叉各走一路，汇合时等所有入边都到 | 定义 |
| 包容网关 | 条件成立的都走，汇合时只等实际走了的分支 | 定义 |
| 自动节点 | 执行使用方注册的动作（发通知、写业务表、生成另一个流程），失败重试，最终失败转人工处理 | 定义；扩展点；表 `flow_job` |
| 调用流程（子流程） | 同步：等子流程结束再往下，子流程的结果决定走哪条出边；异步：发起后不等。父子关系与来源可追溯 | 定义；表 `flow_instance` |
| 定时等待 | 等到某个时刻、等 N 个工作日 | 定义；表 `flow_job` |
| 等待外部事件 | 等业务系统回填（例如线下谈判的结果），收到事件再往下 | 定义；接口 |
| 抄送节点 | 走到时抄送给指定的人、部门或角色，不阻塞流程 | 定义；表 `flow_cc` |
| 条件 | 可序列化的表达式树（比较、全部、任一、取反），与组件库、query 同一套规则；自定义判断写成接入方注册的计算值 `fn.名字`；不写脚本 | 定义；扩展点 |
| 连线的副作用 | 走这条线时改流程变量（赋值、计数加一），用于协商轮次之类 | 定义 |
| 退回、提级连线 | 画在图上的退回与提级，决定目标节点怎样分配处理人 | 定义 |
| 业务附加信息 | 节点对应的业务状态等，引擎原样保存不解释 | 定义 |

## 3. 处理人

落实：0005 的第 3 节与 5.2、5.6，0007 的 `flow_candidate`。

| 能力 | 说明 | 落在 |
| --- | --- | --- |
| 角色收件箱 | 进角色（或部门）的收件箱，有这个角色的人认领，先认领先得；"岗位"由接入方绑定到角色或扩展（0005 的 3.1） | 定义；表 `flow_candidate` |
| 指定的人、发起人、同某节点的处理人、表单字段或流程变量里的人 | 内置的几种（`{ ref }` 取值） | 定义 |
| 上一步选下一步的处理人 | 提交时由这一步的处理人选（审批面板的"选择下一处理人"） | 定义；接口 |
| 扩展的候选种类 | 岗位、项目组这类由接入方注册，操作人的归属由 `Actor.groups(种类)` 给出 | 扩展点 |
| 解析器 | 部门负责人、上级、角色、发起人的第 N 级上级等，由使用方注册，名字写在定义里 | 定义；扩展点 |
| 多个候选 | 一个待办有几个候选人、候选角色或部门 | 表 `flow_candidate` |
| 会签 | 全部通过、任一通过、按比例、按票数，以及依次（一个接一个）；一票否决 | 定义 |
| 加签、减签 | 运行时增减会签参与人；前加签（先给别人处理，再回到自己）、后加签、并加；加签与委派都生成子待办 | 接口；表 `flow_work_item` |
| 处理人为空时 | 自动通过、转给管理员、报错，三选一 | 定义 |
| 自动跳过 | 处理人和上一步相同、处理人就是发起人时自动通过（可选） | 定义 |
| 外部参与方 | 外部账号（供应方之类）也能是处理人；主账号与子账号的动作权限由操作拦截判断 | 扩展点 |
| 休假代理 | 待办要落到不在岗的人时换成代理人（代理人也不在岗时接着找），待办记下代谁处理，被代理的人照样能看实例；代理关系与时段由接入方维护 | 扩展点（`OrgDirectory.standIn`）；表 `flow_work_item` |

## 5. 处理动作

| 能力 | 说明 | 落在 |
| --- | --- | --- |
| 处理 | 按处理结果完成；必填项、守卫、表单的后端代码校验通过才能提交；表单的值按节点的字段权限提交，流程变量由连线副作用改 | 接口；扩展点 |

## 8. 通知

落实：0005 的第 8 节（定义里可以按事件换模板、加收件人、关掉）。

到达、催办、即将到期、超时、抄送、结果（通过、否决、退回）都发事件。渠道由使用方注册（站内信、邮件、企业微信、钉钉），引擎只给出收件人、事件与模板参数。

## 10. 权限、审计与运维

落实：0006 的第 5、6 节，0007。权限默认全部放行，交给接入方（0004 第 6 节的宽松原则）。

| 能力 | 说明 | 落在 |
| --- | --- | --- |
| 查看权限 | 参与过的人、相关的角色与部门、发起人、管理员能看；规则可以扩展 | 扩展点 |
| 操作拦截 | 每个命令前后的拦截器：权限、审计、业务校验 | 扩展点 |
| 审计 | 全部流转记录；管理员操作和变量变更都留痕 | 表 `flow_event` |
| 多租户 | 可选；所有表都有租户列（`BIGINT`，不用时是 0），索引以它开头 | 表 |

| 事件监听 | 事务内（可以拒绝、可以同事务写业务表）与提交后（通知、消息队列） | 扩展点 |
| 归档 | 已结束的实例、待办、流转记录、表单的值、抄送按时间搬进归档表（默认关）；流转记录可选按月分表 | 作业；表 `*_archive` |

## 11. 接入

落实：0001 的"模块划分"，0006 的第 7 节。

| 能力 | 说明 |
| --- | --- |
| Java | `flow-core`（不依赖 Spring）、`flow-spring`（自动配置、事务、扩展点按 Bean 注册，默认实现都可替换），可选的 HTTP 接口 |
| TypeScript | 核心包（不依赖框架）、Nuxt 模块（服务端路由、扩展点注册），可选的 HTTP 接口；两个后端的 HTTP 接口完全相同 |

| 一致性 | 两个后端跑同一套场景用例：给定定义和一串命令，比对待办、流转记录和实例状态 |

## 12. 表单

方案见 [0004](0004-forms.md)。

| 能力 | 说明 | 落在 |
| --- | --- | --- |
| 代码表单 | TSX 源码，保存时编译，源码、编译结果、字段清单一起存；只能导入登记过的模块 | 表 `flow_form`、`flow_form_version`；扩展点（模块登记） |
| 拖拽设计器 | 读写同一份源码，拖拽与手改代码互通 | 前端 |
| 草稿与版本 | 同流程定义：草稿防覆盖，发布后不可变；流程发布时固定引用的表单版本 | 表；接口 |
| 字段权限 | 节点上按字段名给只读、隐藏、必填；前端按它渲染，后端提交时再校验 | 定义；接口 |
| 显示与必填条件 | 字段清单里的 `visibleWhen`、`requiredWhen`（条件树）：前端按它显示、标必填，后端用同一份条件再校验 | 表单；模型包 |
| 表单的值 | 单独存在 `flow_form_data`（每个实例一行），不放进流程变量；条件里写成 `form.字段名`；写业务表在表单的后端代码里做，与流转同一个事务 | 表；接口；扩展点 |
| 一个流程一张表单 | 表单标识写在流程级，节点上只写权限；流程发布时固定表单版本 | 定义 |
| 表单的后端代码 | 在线编辑、存数据库、启动时加载（Spring Boot 用 Java、Nuxt 用 TS）：带出初始值、后端校验、后端算的字段、写业务表、给前端调的接口 | 表 `flow_form_version`；接口 |
| 集群刷新 | 发布后通知其他实例重新加载：引擎只给"发出 / 收到"两个口子，消息队列由接入方接（Kafka、Redis Stream 等），引擎给示例 | 扩展点 |

## 13. 后来补进的能力（2026-10-26，讨论 0004–0007 时加的）

| 能力 | 说明 | 落在 |
| --- | --- | --- |
| 标准行为都能替换 | 每一种标准行为都放在接口后面，接入方不满意就换成自己的（原则，0001 的定位） | 全部 |
| 实例标题 | 按模板生成（`"采购申请：{form.title}"`），每次提交重新生成 | 定义（0005 第 2 节） |
| 发起范围 | 谁能发起：角色、部门、指定的人、解析器 | 定义 |
| 紧急程度 | 实例的 `priority`，抄到待办上排序 | 表；接口（`start` 的参数） |
| 发起前存草稿 | 发起前填了一半先存（实例状态 `draft`） | 接口 |
| 预测下一步 | 选了某个处理结果后会走到哪些节点、哪些要选处理人 | 接口（`predict`） |
| 已读 | 待办第一次打开的时间，列表里标"新" | 表 `flow_work_item` |
| 异常处理待办 | 自动节点重试用完后给管理员的待办：重试、指定结果继续、终止 | 表；接口 |
| 自定义节点类型、会签规则 | 接入方注册 `x-名字` 的节点类型、新的会签完成规则 | 扩展点（0005 第 9 节） |
| 计算值 | 接入方注册 `fn.名字`（`ComputedValue`），连线条件里比较；每次用到都算 | 扩展点（0005 的 6.1） |
| 扩展目录 | 注册的扩展各自用 `info()` 给出显示名、说明、参数、可能的结果，设计器从 `GET /queries/extensions` 读：名字下拉选、参数按声明画控件、自定义节点进节点列表、校验认得这些名字 | 扩展点；接口 |
| 节点的业务信息 | 接入方声明 `meta` 有哪些字段（`flow.designer.node-meta`），设计器按它画表单；引擎原样保存，接入方的监听读它 | 配置；定义 |
| 关掉在线后端代码 | `flow.forms.server-code: false`：发布带后端代码的表单报 `server-code-disabled`，已存的也不执行，表单编辑器不显示后端代码页签 | 配置 |
| 主键 | 数据库自增的 `BIGINT`（Java 的 `long`）；用户 2026-10-26 改定，不用雪花（0006 的 6.1） |
| 自定义字段类型 | 表单字段类型可以注册新的（带币种的金额之类） | 扩展点（0004 的"可替换的部分"） |
| 按业务表生成代码 | 表单后端代码页签里选表、选列，生成 `load` / `submit` 的代码 | 设计器（0004 的"已定"） |
